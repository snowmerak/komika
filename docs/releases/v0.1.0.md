# Komika v0.1.0

Komika is a local-first, cross-platform comic reader built with Wails v3, using a Go backend and a TypeScript frontend.

The initial release supports comic archives, media folders, standalone media files, PDFs, and Markdown documents through a unified reader interface.

## Highlights

### Broad format support

Komika can open:

* CBZ / ZIP
* CBR / RAR
* CB7 / 7z
* Image and media folders
* PNG, JPEG, WebP, and animated GIF
* WebM, MP4, and MOV video
* MP3, M4A, AAC, OGG, Opus, and WAV audio
* PDF
* Markdown

You can also drag and drop a single file or folder directly onto the application window.

### Comic-focused reading modes

Available view modes include:

* Fit window
* Fit width
* Fit height
* Original 100%
* Double-page LTR
* Double-page RTL
* Continuous webtoon strip
* Optional stretching of small images
* Manual zoom from 25% to 800%
* Zoomed-content panning with the mouse wheel or `Alt` + drag

### Multiple image scaling modes

Komika provides several scaling options for different kinds of artwork and source material:

* Smooth
* High quality using Lanczos-3
* NoHalo
* xBRZ
* Pixelated

Lanczos-3, NoHalo, and xBRZ are applied to the settled viewport tile after zooming or panning. Animated GIFs remain animated and bypass canvas-based filters.

### PDF and Markdown support

PDF files are rendered with pdf.js, with each PDF page represented as a reader page.

Markdown files are rendered as scrollable article pages using Merak's `merak-protocol-design-system/markdown` renderer.

### Large media handling

Komika uses different delivery paths depending on page size and media requirements:

* Pages up to 32 MiB use in-memory RPC
* Larger media uses same-origin streaming
* Seekable archive members are temporarily extracted
* Temporary extraction is limited to 2 GiB per entry
* Active-comic aggregate temporary-cache limits are enforced
* Streams become unavailable when the opened source is moved or deleted

### Local library and resume progress

The initial library implementation includes:

* Up to 20 recent works
* Per-work resume progress
* Optional recent-history and progress storage
* Configurable retention:

  * Forever
  * 7 days
  * 30 days
  * 90 days
* Remove one item
* Remove selected items
* Clear all history
* Clear stored history when saving is disabled

Recent history is stored in the operating system's user configuration directory:

```text
${os.UserConfigDir()}/komika/library.json
```

View preferences and toolbar state are stored in `localStorage`.

## Reader controls

| Key                                           | Action                                |
| --------------------------------------------- | ------------------------------------- |
| Arrow keys / WASD / Space / PageUp / PageDown | Turn pages                            |
| Shift + navigation key                        | Page jump in webtoon mode             |
| Home / End                                    | First / last page                     |
| `+` / `-`                                     | Zoom in / out                         |
| Shift + `+` / `-`                             | Fine zoom adjustment                  |
| `0`                                           | Original 100%                         |
| `1` / `9`                                     | Fit window                            |
| `8`                                           | Fit width                             |
| `H`                                           | Fit height                            |
| `7`                                           | Double-page LTR                       |
| `6`                                           | Double-page RTL                       |
| `5`                                           | Webtoon mode                          |
| `Z`                                           | Toggle stretching of small images     |
| `T`                                           | Collapse or expand the reader toolbar |

Double-clicking the reader title or toolbar chrome maximizes or restores the application window.

## Known limitations

* Encrypted archives are not supported.
* Multi-volume archives are not supported.
* Dropping multiple files at once is rejected.
* Video and audio playback depends on codec support provided by the host WebView.
* Unsupported codecs are shown as in-reader error cards.
* Unreadable PDFs inside multi-entry sources are skipped.
* Platform packaging and code signing may vary between release artifacts.
