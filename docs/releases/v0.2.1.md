# Komika v0.2.1

**Changes since [v0.1.0](./v0.1.0.md)**

This release focuses on reliable media playback (especially on Linux WebKitGTK), OS “Open with” integration, PDF/webtoon layout, and Docker-based multi-arch packaging.

## Highlights

### Media playback that works when the WebView cannot

* **Host ffmpeg fallback** — When the embedded WebView cannot decode a clip, Komika can transcode via system `ffmpeg` to VP8/Opus WebM (video) or Opus Ogg (audio), with clearer errors and a frontend retry path.
* **ffmpeg.wasm fallback** — Small clips can fall back to a bundled wasm transcoder when host codecs still fail.
* **Linux WebKitGTK streaming** — Video/audio are served over loopback HTTP with **Range** support (instead of Wails blob URLs), with clean MP4 remux preferred before WebM transcode.
* **MP4 faststart** — Archives whose `moov` atom sits after `mdat` are remuxed with ffmpeg before streaming so progressive playback can start.
* **Stall recovery & soft-loop** — Progress watchdog, resume after unexpected pauses, revive frozen WebKit videos after `ended`, and soft-loop seamless repeats without tearing down the player.
* **Playback diagnostics** — Collapsible technical details on unavailable media cards, plus a live diagnostics panel under video (attach / stall / error events).
* **Windows** — ffmpeg / faststart subprocesses no longer flash a console window.

### Linux packaging & codecs

* AppImage **GStreamer plugin inject** (libav + good/base/bad/ugly tools path) so H.264/AAC can play inside the AppImage.
* Native **deb/rpm** depends tightened for libav + plugins-good (ffmpeg recommended for host fallback).
* README (EN / KO / JA) documents distro package names for H.264/AAC.

### Open with & file associations

* Register comic and media types across **Linux, macOS, Windows, and iOS** build assets.
* Second-instance / `ApplicationOpenedWithFile` paths are queued for the UI.
* Linux **XDG** desktop integration install / status / remove APIs and settings UI.

### PDF & webtoon

* PDF pages retained via a cache window (not only when strictly visible).
* Webtoon layout can reserve space for PDF pages; markdown/PDF loading shells improved.

### Docker multi-arch packaging (Debian 13)

Full **Linux** (AppImage / deb / rpm / aur) and **Windows NSIS** packaging inside `komika-package` images (`debian:trixie`), without a matching host toolchain.

```bash
wails3 task package:docker:setup ARCH=amd64   # or arm64
wails3 task package:docker GOOS=linux ARCH=amd64
wails3 task package:docker GOOS=windows ARCH=amd64
```

* One image tag per arch: `komika-package:amd64` / `:arm64`.
* `package:docker` always uses `komika-package:$ARCH` and `--platform linux/$ARCH` (build that image first).
* Non-host arch needs qemu/binfmt; AppImage tools under qemu use `run-appimage` / `qemu-user-static`.
* Binary-only cross-compile remains `wails3 task setup:docker` → `wails-cross`.

Primary artifacts under `bin/`:

| Target | Examples |
|--------|----------|
| Linux amd64 | `komika`, `komika-x86_64.AppImage`, `komika*.deb` |
| Linux arm64 | `komika`, `komika-aarch64.AppImage`, … |
| Windows amd64 | `komika.exe`, `komika-amd64-installer.exe` |
| Windows arm64 | `komika.exe`, `komika-arm64-installer.exe` |

### Housekeeping

* Expanded `.gitignore`; dropped tracked Android Gradle file-hash caches and local AppImage noise.
* Supported platforms listed in the README.

## Upgrade notes

* **Linux (native package / unbundled binary):** install GStreamer **libav + plugins-good** (and preferably base/bad/ugly + tools) for H.264/AAC in WebKitGTK. Install **ffmpeg** for the host transcoder fallback.
* **AppImage:** rebuild with `task package` / `package:docker` so GST inject runs; do not ship a pre-inject AppImage if video codecs matter.
* **Docker packaging:** run `package:docker:setup ARCH=…` once per arch before `package:docker`.
* Version metadata in `nfpm.yaml` / Windows `info.json` may still show template `0.0.1` until bumped for the tagged release build.

## Known limitations (carried forward / updated)

From v0.1.0, still true unless noted:

* Encrypted and multi-volume archives are not supported.
* Dropping multiple files at once is rejected.
* Unreadable PDFs inside multi-entry sources are skipped.
* Platform packaging and code signing may vary between release artifacts.
* **Updated:** video/audio no longer depend only on host WebView codecs — host `ffmpeg`, AppImage GStreamer inject, and wasm fallback cover many previously unsupported clips. Remaining failures still surface as in-reader error cards with diagnostics.
